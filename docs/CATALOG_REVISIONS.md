# 精确目录事务审批与发布控制

## 信任边界

- 唯一受信入口：发布器代码仓库内固定相对位置 `config/catalog_revisions.json`。初始模板的 `approvals` 为空；仅在所有者明确批准后登记该事务指纹。存在许可不表示数据已经发布，也不免除独立删除批准和保护环境审批。
- `Snapshot.commits/warnings`、Markdown/YAML 自声明、源目录内同名文件、环境变量、dispatch 或普通删除批准字符串都不能提供本许可；无策略路径参数。
- SHA256 不是签名，不能证明是谁批准；防伪范围来自受控代码仓库的策略维护权限。必须用代码审核/所有者流程保护配置，不能让不受信源编辑它。
- 每个批准条目仅为一个 SHA256；不含业务牌号或内部路径。指纹输入为 canonical JSON：`schema`、完整 `before` 路径→业务SHA256映射、完整 `after` 映射、按 `category/path` 排序的精确豁免集合。任一业务字节、路径、基线或范围变动都会失效。
- 先完整运行既有 `check_identity`，再逐项分类资格，最后匹配受信指纹；不是匹配后清空全部违规。未分类的 identity 违规及全部其它门禁保留。

## 最小资格（故意保守）

1. 原所有产品完整 ID 必须按原拼写继续存在；不允许新增产品身份、RD→RS、跨后缀替换、大小写修号或用短前缀/数量抵偿。可移除的唯一产品身份是无后缀大写 `RS/RD+ASCII数字` 基号；该基号必须已有非空后缀产品，且其所有原完整后缀产品逐一仍在。本例外只豁免该具体 family 的 `identity-suffix-merged`。
2. 配方只可豁免 `stem-collision-cross-namespace`、`identity-suffix-dropped`，不涉及应用/TDS 同名、产品命名畸形、重复或其它身份类别。
3. 原/新配方按已登记产品的最长完整 prefix 归属。路径尾部只接受原有 `亮/哑/银/黑/底` 用途以及 `参考配方`、`方案数字`、`方案RS数字[-段]` 采编尾；旧 `参考配方-方案RS数字[-段]` 允许且仅允许追加一次 `-方案数字` 二次顺位。未知尾缀仍拒绝；已登记的更长完整产品名永远优先，不能剥成采编尾。这些字不证明真实用途，所有者仍须回原件审核。
4. 保留的新主方及至少一个同 owner 旧主源须有一张可见的真实五列原料表（代码围栏、引用、注释、示例区无资格），标量 `关联产品` 包含完整 owner 且全部引用有真实产品入口。owner 必须实际正量投料；完整消费原料格，只支持本号原文、单个本号双链、单个本号双链后附 `(浓度%)`（浓度严格大于0且不超过100）、或有来源的 `主体树脂（[[完整本号]]）` 包装；不改原格值、浓度和来源，不按子串或任意双链认 owner。
5. 新主方的全部 `(原料原文, 原投料原文)` 按顺序必须等于一个实际撤出的同 owner 旧主方；不删原料/范围/未知后加行，不做料号或数值归一。同BOM所有合并旧成员的已登记共享产品关联须取并集保留，不能挑一条弱关联来源绕过。另有不同BOM或不可定量旧方退选，不等于化学BOM合并：其旧路径仍须按最长已登记完整 owner 精确归属，但无需可作保留主方，也不强挂其旧辅助树脂。短前缀检测同时命中另一个完整 owner 的旧路径时，按最长完整 owner 分组；仅当该 owner 有独立保留主方，且其保留BOM与真实同owner旧主源逐行全等、同BOM共享关联并集完整保留，才允许该组自己的其它旧方案在本次精确事务中退选；不把它们并入短前缀产品。缺独立完整主方、跨owner借方或真实后缀缺失仍拒绝。所有退选字节和精确 category/path 仍被完整事务指纹绑定。
6. 特殊事务数量语法仅覆盖非负数/有序范围、`适量/少量/另加/按当量另加/按NCO/OH=数字另加/开稀至可喷粘度`，以及 `适量（NCO/OH=下限-上限）`（正数且不倒置）；不接受任意中文、金额或追加句子。未知量原行保留，不填0、不计算最终全料百分比；表外另加与实际范围不因此被丢弃。多配方块或其它合法用途仍可能拒绝，须另建测试后审核扩展，不能用任意字符串/源声明扩大资格。

## 接入与审计

`quality_gate.evaluate` 读取固定策略，并记录独立 `catalogRevision`（used、fingerprint、scopeSha256、exemptedCount）。不把已用许可伪装成从未触发违规，也不增加/删除已有 warning；无许可时报告原有摘要结构不变。

真实 `prepare/resume/promote/complete/package` 经既有质量接入点重新验证策略与精确基线；撤销配置会阻断后续出口。原 `build.py`、`release.py`、`identity_migrations.json` 与默认删除比例 0.25 原字节不改，批量路径删除仍需原删除指纹批准。回滚不消费此正向许可，也不扩张旧灾难恢复语义；含特殊同名复杂配方的历史载荷不能借正向许可回滚。

## 只提案的本地 CLI

在代码根目录，使用现有 Python 环境：

```sh
PYTHONPATH=scripts python3 -m rstone_data.catalog_revisions \
  --before BASELINE_TREE --after FINAL_CANDIDATE_TREE
```

支持门禁原有 `产品列表/...`、`files/...`、`Rstone/+RstoneTDS/` 布局。只读本地树，stdout 输出指纹/范围哈希/计数，始终 `approved: false`。完整可提案范围返回 0；无资格、仍有未豁免身份违规或输入不可读返回 1。提案成功不代表其它质量门禁通过、更不代表获准签名或部署。最终批准必须另走所有者对精确前后字节及删除指纹的受控审核；本工具不编辑策略、不签名、不建CAS/pending/ZIP。

## 已知边界

- 此机制不冻结任何文件总数，不追求清零预检类别；实际事务仍由其完整前后业务字节及精确范围定义。
- 真实前后目录已只读重放；资格差分、未获资格项、完整摘要及保护SHA只保留在私有验收日志，不写入策略或公开补丁。
- 回归测试仅用合成数据真实跑签名/打包；测试签名不充当真实生产签名，正式发布仍须走受控工作流。
- 回归分别验证已安装策略精确加载、空策略不授权，以及完整号、价格、内容、签名和删除保护的合成正反例；各阶段的 warning、违规和资格计数分别报告，不把可提案范围冒称实际已豁免。
